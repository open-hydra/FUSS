# The coupled ablating wall 307, four blocks (plan 11 stage 4)

`run307` (the coupled ablating wall 307 standalone: TACOT, the type-2 gas closure, both cells of face 2 typed 307, the
exchange values from the TEST ONLY `[FUSS-Ablation] coupled-env-file`, one table for both faces) cut into 4 × 1
blocks of 25 × 2 cells along x. Block 4 holds the two 307 faces. Equal blocks go to the ranks in order
(`partition_blocks`, greedy on the least load), so the faces live on rank 3 at four ranks and on rank 1 at two.

This is hydra's contract for a split coupled run, with FUSS standalone. hydra writes a 307 face's exchange values
(`bc%env_now`) on the rank of the face's block only, and since plan 11 stage 4 the TEST ONLY table is read the same
way. The run therefore needs the following:
- `Ablation_Update_Env` skips the faces of another rank's blocks. Without the skip, ranks 0 to 2 stop at the first
  step: "no exchange values (p_w = 0)".
- root's `seb.txt` gets the faces' rhoeUeCH0 and h_r from their rank, among the 25 values per face of
  `Gather_Face_Outputs`. Without them, root prints zeros there.
- the Darcy solve runs across the three cuts (one correction group of blocks in a row).

The 307 record's second line (`1 1 1 1 1 1 0 0 1  300.0, bprime_tacot_earth.dat`) names the coupled solver's cell,
not a FUSS one. The split keeps it verbatim.
